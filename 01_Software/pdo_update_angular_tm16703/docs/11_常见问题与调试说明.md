# 常见问题与调试说明

## 1. 为什么上位机已经发了速度命令，车还是不动？

常见原因有 5 个：

- 当前不在 `MODE_REMOTE + SUB_SLAVE`
- 只发了单轮命令，没有同时发送 `0x01 + 0x02`
- 会话已超时，`uart_session_is_alive()` 为假
- drive 命令已过期，`uart_drive_cmd_is_fresh()` 为假
- host power-policy 把左右轮置为 disable

## 2. 为什么切到从机模式后，第一帧旧命令不生效？

这是设计行为。进入 `SUB_SLAVE` 时会记录当时的 `drive_cmd_seq/lift_cmd_seq`，只有切入后收到的新命令才允许执行，避免模式切换瞬间执行旧命令。

## 3. 为什么系统没有返回 ACK？

当前实现只支持：

- `Telemetry(0x01)`
- `Command(0x81)`

不发送 `ACK(0x02)`。主机端应通过后续遥测判断命令是否被真实执行。

## 4. 为什么状态字和主机下发的 `status_value` 不一样？

因为上传的 `status_word` 是“真实执行状态”，不是“主机意图回显”。例如主机要求 enable，但电机还没真正上电时，上传状态不会伪装成已使能。

## 5. 为什么升降命令合法，但关节不响应？

优先检查：

- 关节是否已回零
- 回零状态机是否还在 busy
- 当前是否处于 `SUB_SLAVE`
- host 是否把关节 disable
- 上下限位是否异常

## 6. 为什么 `bucket_volume` 一直没有上传？

当前版本没有接入真实水量传感器，因此 `bucket_volume_valid=0`，协议层不会发送 `0x04`。

## 7. 为什么 READY 模式下电机不上电？

因为默认配置 `SYSTEM_CFG_READY_KEEP_DRIVE_POWER=0`，`MODE_READY` 被定义为无力矩安全待机。若现场需要带电待命，必须修改编译开关并重新联调验证。

## 8. 为什么偶尔收不到完整串口数据？

优先检查：

- 主机是否按 `115200 8N1` 配置
- 帧头、长度、CRC 是否正确
- UART1 DMA 中断是否正常触发
- `uart_get_diag()` 中是否出现 `rx_drop_bytes` 或 `rx_overflow_cnt` 增长

## 9. 如何确认命令到底有没有进入控制层？

建议依次查看：

1. `host_control_cmd_snapshot()`
2. `robot_mode_snapshot()`
3. `robot_motion_cmd_snapshot()`

如果 mailbox 已更新但运动命令未更新，说明问题在模式机或命令仲裁，不在通信层。

## 10. 如何判断是 CAN 问题还是控制逻辑问题？

方法：

- 若 `robot_motion_cmd_snapshot()` 正常，但电机状态没有变化，优先怀疑 CAN/驱动
- 若 `mcu_can_diag_snapshot()` 中 `busoff_count` 或 `recover_fail_count` 增长，优先排查总线
- 若控制命令根本没有生成，则优先排查模式和通信

## 11. 关节回零失败时应该先看什么？

先看 3 项：

- `motor_task_joint_home_status_snapshot()`
- `input_driver_get_status()` 中 `limit_lower`
- `motor_runtime_snapshot(MOTOR_INDEX_JOINT)`

通常先判定是“限位没触发”、“电机没使能”还是“超时进入 fault”。

## 12. 现场临时调试建议

- 串口问题先看 `uart_get_diag()`
- 执行问题先看 `robot_motion_cmd_snapshot()`
- 电机问题先看 `motor_info_snapshot()` 和 `motor_runtime_snapshot()`
- 关节问题先看回零状态机
- 总线问题先看 `mcu_can_diag_snapshot()`

# 当前权威说明（2026-03-13）

以下问答优先于上文旧结论。

## 为什么没有连接遥控器，上位机现在也能控制底盘？

因为当前默认打开：

- `SYSTEM_CFG_ALLOW_HOST_SLAVE_WITHOUT_IBUS = 1`

这意味着：

- `IBUS` 未连接时，只要上位机持续发送新鲜的 `drive/lift` 命令，模式机会自动切到 `MODE_REMOTE + SUB_SLAVE`

## 为什么没有连接遥控器，上位机还是控制不了底盘？

优先检查：

1. 上位机是否持续发命令，而不是只发一帧
2. `uart_session_is_alive()` 是否为真
3. `uart_drive_cmd_is_fresh()` 是否为真
4. `robot_mode_snapshot()` 是否已经进入 `MODE_REMOTE + SUB_SLAVE`

## 为什么 READY 模式下电机现在是上电状态？

因为当前默认：

- `SYSTEM_CFG_READY_KEEP_DRIVE_POWER = 1`

这表示 `MODE_READY` 允许驱动轮保持上电，但不代表 READY 下就会执行上位机底盘运动命令。

## 当前补充说明（2026-03-13）

### 为什么进入导航模式后电机没有自动掉电？

因为当前默认打开：

- `SYSTEM_CFG_HOST_SLAVE_KEEP_DRIVE_POWER = 1`

这表示：

- 进入 `MODE_REMOTE + SUB_SLAVE` 后，驱动轮保持上电。
- 上位机会话短暂中断，不会再自动掉电失能。

### 为什么没有连接遥控器，上位机现在也能控制底盘？

因为当前默认打开：

- `SYSTEM_CFG_ALLOW_HOST_SLAVE_WITHOUT_IBUS = 1`

这表示：

- `IBUS` 未连接时，只要上位机持续发送新鲜的 `drive/lift` 命令，模式机会自动切到 `MODE_REMOTE + SUB_SLAVE`。

### 什么时候还会真正失能？

以下情况仍会使驱动轮失能：

- 急停触发。
- 主机会话仍有效，且 `power-policy` 明确要求 disable。
- 模式退出 `MODE_REMOTE + SUB_SLAVE`，且当前模式不允许保电。
