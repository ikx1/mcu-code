# SM16703 灯带适配说明

## 1. 结论

当前 RGB 灯带已从历史 `WS2811/WS2812` 基线切换到 `SM16703P/TM16703`。

本次适配没有改动业务层灯效任务接口，仍沿用：

- `ws2811_set_pixel()`
- `ws2811_all_same_color()`
- `ws2811_show()`

这样可以保证 `User/ws2812_task/ws2812_task.c` 无需跟着重写。

## 2. 手册结论

根据 `demo/LED驱动_SM16703P.PDF`，`SM16703P/TM16703` 的关键特性如下：

- 单线串行级联，不是独立 `CLK + DATA` 两线协议。
- 传输速率为 `800Kbps` 量级。
- 采用归零码输出，每一 bit 都会回到低电平。
- `RGB` 数据格式仍为 `24bit / pixel`。
- 复位锁存低电平时间要求不低于 `200us`。

因此，当前工程可以继续复用 `TIM3 + DMA + 单线 PWM` 的发送框架，不需要重做成 `SPI/I2C` 类驱动。

## 3. 实际改动

本次只调整了底层时序，不改高层灯效逻辑。

### 3.1 位周期

- 继续使用 `TIM3_CH2(PA7) + DMA1_Channel3`
- `TIM3_ARR_VALUE = 89`
- 在 `72MHz` 定时器时钟下，对应 `1.25us / bit`

### 3.2 单 bit 高电平宽度

为匹配 `SM16703P` 的时序窗口，当前占空比改为：

- `0` 码高电平约 `0.30us`
- `1` 码高电平约 `0.90us`

对应代码位置：

- `BSP_Plantform/Bsp_Drivers/ws2812/driver/bsp_ws2812_driver.h`

### 3.3 颜色通道顺序

当前实物灯带不是标准 `RGB` 字节顺序，而是 `RBG` 顺序。

实测现象：

- 软件下发绿色，实物显示蓝色

因此底层增加了颜色顺序映射宏，当前配置为：

- `WS2811_COLOR_ORDER = WS2811_COLOR_ORDER_RBG`

### 3.4 复位低电平窗口

为满足 `Trst >= 200us`，当前采用两层保护：

- DMA 缓冲尾部追加 `192` 个 `reset slots`
- 发送完成后额外保持 `200us` 复位时间

对应代码位置：

- `BSP_Plantform/Bsp_Drivers/ws2812/driver/bsp_ws2812_driver.h`
- `MCU_Platform/MCU_Core_PWM/pwm_port.c`

## 4. 兼容性说明

虽然底层已经切换到 `SM16703P/TM16703`，但软件接口名称暂时没有改名，仍保留历史 `ws2811/ws2812` 命名。

这样做的原因是：

- 业务层和任务层已经大量引用现有接口
- 当前芯片同样是单线 `24bit RGB` 级联协议
- 这次迁移只需要修改时序参数，不需要推翻模块边界

后续如果需要彻底清理命名，可以单独做一次“接口去历史命名”重构，但不建议和当前板级适配混在一起。

## 5. 受影响文件

本次构建输出目录：

- `MDK-ARM/Build_sm16703/Objects/project.axf`

若后续再次调整灯带型号，优先先确认三件事：

1. 是否仍为单线级联协议。
2. 每 bit 的高电平宽度窗口是否与当前配置兼容。
3. 复位低电平时间是否仍满足 `>= 200us`。
