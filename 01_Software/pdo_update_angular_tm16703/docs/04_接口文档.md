# 接口文档

## 1. UART1 外部协议接口

### 1.1 物理链路

| 项目 | 值 |
| --- | --- |
| 端口 | `USART1` |
| 波特率 | `115200` |
| 数据位 | `8` |
| 校验 | `None` |
| 停止位 | `1` |
| 流控 | `None` |

### 1.2 帧格式

```text
H1 H2 VER SEQ TYPE LEN_L LEN_H PAYLOAD CRC_L CRC_H
```

字段说明：

| 字段 | 大小 | 说明 |
| --- | --- | --- |
| `H1` | 1B | 固定 `0xA0` |
| `H2` | 1B | 固定 `0x0A` |
| `VER` | 1B | 协议版本，固定 `0x01` |
| `SEQ` | 1B | 序号 |
| `TYPE` | 1B | `0x01` 遥测，`0x81` 命令 |
| `LEN_L/LEN_H` | 2B | Little Endian，表示 `PAYLOAD` 长度 |
| `PAYLOAD` | 0..128B | TLV 负载 |
| `CRC_L/CRC_H` | 2B | CRC16(Modbus)，Little Endian，覆盖 `VER..PAYLOAD` |

注意：

- 当前实现不发送 `ACK(0x02)`。
- 历史资料若写成 `CRC_H CRC_L`，以当前代码实现为准，实际发送顺序是低字节在前。

### 1.3 TLV 编码

```text
TAG LEN VALUE
```

约束：

- `LEN` 为单字节
- 同帧允许多个 TLV
- 未识别 `TAG` 直接按长度跳过
- 单个 payload 最大 `128` 字节

## 2. 下发命令 TLV

| Tag | 类型 | 单位 | 含义 | 约束 |
| --- | --- | --- | --- | --- |
| `0x01` | `int32` | `mrad/s` | 左轮角速度 | 必须与 `0x02` 同帧 |
| `0x02` | `int32` | `mrad/s` | 右轮角速度 | 必须与 `0x01` 同帧 |
| `0x03` | `int32` | `mm` | 升降目标高度 | 范围 `0..230` |
| `0x11` | `uint16` | - | `status_mask` | 必须与 `0x12` 同帧 |
| `0x12` | `uint16` | - | `status_value` | 必须与 `0x11` 同帧 |

命令域规则：

- drive 域：`0x01` 和 `0x02` 缺一不可
- lift 域：`0x03` 独立生效
- power-policy 域：`0x11` 和 `0x12` 缺一不可
- 任一域长度错误或数值越界时，只丢弃该域，不连坐其它域

## 3. 上行遥测 TLV

| Tag | 类型 | 单位 | 含义 | 当前实现 |
| --- | --- | --- | --- | --- |
| `0x01` | `int32` | `mrad/s` | 左轮真实角速度 | 已实现 |
| `0x02` | `int32` | `mrad/s` | 右轮真实角速度 | 已实现 |
| `0x03` | `int32` | `mm` | 升降真实位置 | 已实现 |
| `0x04` | `uint16` | `mL` | 水箱余量 | 预留，默认不上报 |
| `0x13` | `uint16` | - | `status_word` | 已实现 |
| `0x14` | `uint16` | - | `health_word` | 已实现 |
| `0x15` | `uint16` | - | `alarm_info` | 已实现 |
| `0x21` | `uint16` | `0.01%` | 电池电量 | 已实现 |

## 4. 状态位接口

### 4.1 `status_value` / `status_word`

| 位段 | 含义 |
| --- | --- |
| bit0..1 | 右轮 power command |
| bit2 | 右轮 reset |
| bit3..4 | 左轮 power command |
| bit5 | 左轮 reset |
| bit6..7 | 关节 power command |
| bit8 | 关节 reset |
| bit12 | spray on |
| bit13 | drain on |
| bit14 | charging on |
| bit15 | gripper closed |

`power command` 编码：

- `0`：none
- `1`：enable
- `2`：disable

### 4.2 `health_word`

当前实现的主要位含义：

| 位 | 含义 |
| --- | --- |
| bit0 | 急停有效 |
| bit1 | 右轮已使能 |
| bit2 | 右轮报警 |
| bit3 | 左轮已使能 |
| bit4 | 左轮报警 |
| bit5 | 关节已使能 |
| bit6 | 关节报警 |
| bit8 | 电池通信故障 |
| bit9 | IBUS 已连接 |
| bit12 | 正在充电 |

### 4.3 `alarm_info`

- 低字节：右轮电机报警码
- 高字节：左轮电机报警码

## 9. 接口变更时的联动修改清单

### 9.1 改协议字段

需要联动：

- `host_cmd_defs.h`
- `host_control_cmd.h`
- `uart_task.c`
- 上位机联调脚本
- `docs/04_接口文档.md`

### 9.2 改状态位语义

需要联动：

- `host_status_defs.h`
- `uart_task.c` 中的 `status_mask/status_value` 解码逻辑
- `telemetry_service.c` 中的 `status_word/health_word` 生成逻辑
- 上位机状态位解释代码

### 9.3 改软件接口签名

需要联动：

- 对应头文件
- 全部调用点
- 文档
- 若接口给上层模块调用，还要更新调试手册和测试用例

## 10. 建议的接口使用方式

### 10.1 读取共享状态

统一使用 snapshot 接口，不要直接访问静态变量：

- `host_control_cmd_snapshot()`
- `robot_mode_snapshot()`
- `robot_motion_cmd_snapshot()`
- `drive_feedback_snapshot()`
- `telemetry_service_snapshot()`

### 10.2 新增共享状态

建议遵守以下模板：

1. 在头文件里定义结构体和 snapshot 接口
2. 在 `.c` 文件里保留静态对象
3. 所有写操作都走单一入口
4. 读操作统一走 snapshot

### 10.3 不建议的接口使用方式

- 不要直接引用别的模块内部静态变量
- 不要跨层直接调用下层驱动写硬件
- 不要为了“省一步”跳过 snapshot 机制
