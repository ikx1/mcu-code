# WS2811问题复盘

## 1. 问题背景

本次 `STM32F103VET6` 迁移后，`WS2811/WS2812` 灯带不是一次性稳定，而是经历了多轮定位和修正。这个文档专门总结灯带问题，避免后续再次把已经验证失败的方案带回工程。

## 2. 现场现象

本次联调过程中，先后出现过以下现象：

- 前几个灯珠显示异常
- 第一颗灯珠上电后能亮，但状态切换后颜色不变化
- 第一颗灯珠和其它灯珠变色不同步，延迟大约 `0.5s`
- 某一版修改后整条灯带开始闪烁，比前一版更严重

这些现象并不完全一样，但都集中指向链头第一颗灯珠最敏感的两个阶段：

- 帧起始数据对齐
- 帧结束后的 reset latch 低电平

## 3. 过程中验证过的错误方向

以下方案已经在当前板子上验证过，不稳定或会引入新问题：

### 3.1 直接沿用旧平台参数或资源描述

- 把旧 `F429` 的 `TIM3_CH3(PB0)` 当作当前板级配置
- 沿用不匹配当前时钟的旧时基理解

问题：

- 当前硬件实际是 `TIM3_CH2(PA7) + DMA1_Channel3`
- 平台和时钟基线已经变化，不能机械照搬旧平台描述

### 3.2 手动先发首 bit，再让 DMA 从第二个 compare 开始

这种方案在链头像素上风险很高。

问题：

- 第一颗灯珠最容易因为首 bit 装载/更新时序不稳定而出错
- 会出现“前几颗异常”或“第一颗不跟随变化”的现象

### 3.3 发送结束后切换 `PA7` 为普通 GPIO 并强制拉低

这版在现场已经证明更差。

问题：

- 灯带会闪烁
- 第一颗问题没有真正消失
- 引脚模式切换本身打坏了稳定的 PWM/DMA 节奏

结论：

- 不要再通过 `AF_PP <-> GPIO` 模式切换去制造 latch 低电平

## 4. 最终稳定方案

当前已经验证稳定的实现如下：

- 输出资源：`TIM3_CH2(PA7) + DMA1_Channel3`
- 位周期：`TIM3_ARR_VALUE = 89`
- 数据发送方式：整帧 DMA
- 帧尾处理：缓冲尾部追加 `64` 个 reset slots

对应设计含义：

1. 不再拆开发送首个 compare。
2. 不再依赖停 PWM 后引脚“自然低电平”。
3. 直接在 DMA 数据流尾部补足明确的低电平窗口，让第一颗灯珠稳定完成锁存。

## 5. 最终有效的关键结论

这次问题真正解决靠的是下面这组组合，而不是单一参数：

- `TIM3_ARR_VALUE = 89`
- 固定使用 `PA7` 复用推挽输出
- 整帧 DMA 发送
- DMA 缓冲尾部补 `reset low slots`

其中最关键的一点是：

- reset latch 低电平要由 DMA 帧尾明确生成，不要靠模式切换“补救”

## 7. 后续维护注意事项

1. 不要再恢复 `PA7` 模式切换拉低的方案。
2. 不要再恢复“手动首 bit + DMA 从第二项开始”的方案。
3. 如果后续又出现第一颗异常，先确认 `reset slots` 是否仍然保留。
4. 如果软件基线没变但现场仍异常，优先检查首颗灯珠硬件、供电、地线和数据线焊接。
