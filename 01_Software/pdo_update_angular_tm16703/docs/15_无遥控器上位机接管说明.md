# 无遥控器上位机接管说明

## 1. 目的

本文档说明当前 `STM32F103VET6` 版本下，在没有连接遥控器的情况下，如何通过上位机继续控制底盘，以及这条行为由哪些配置控制。

## 2. 当前行为

当前工程默认打开：

- `SYSTEM_CFG_ALLOW_HOST_SLAVE_WITHOUT_IBUS = 1`

因此在 `IBUS` 未连接时，只要上位机持续发送新鲜的 `drive/lift` 命令，模式机会自动切到：

- `MODE_REMOTE + SUB_SLAVE`

结论：

- 没有遥控器时，上位机也可以接管底盘。
- 这不是异常，而是当前版本的显式设计行为。

## 3. 触发条件

无遥控器时，上位机接管成立需要同时满足：

1. `uart_session_is_alive()` 为真。
2. `uart_drive_cmd_is_fresh()` 或 `uart_lift_cmd_is_fresh()` 为真。
3. 急停未触发。

额外说明：

- `SUB_SLAVE` 的 epoch 保护仍然保留。
- 因此切入后必须继续收到新的命令帧，底盘才会真正开始运动。
- 只发送一帧旧命令，不会让底盘持续运行。

## 4. 关闭这条行为的方法

如果不希望无遥控器时上位机接管底盘，把下面这个宏改回 `0`：

- `SYSTEM_CFG_ALLOW_HOST_SLAVE_WITHOUT_IBUS`

修改后需要重新编译并重新下载程序。

## 5. 与其他安全逻辑的关系

这条功能不会绕过现有安全逻辑：

- 急停仍然是最高优先级。
- 上位机命令超时后，系统仍会回到 `MODE_READY`。
- 上位机 `power-policy` 里的 disable 仍然有效。

## 6. 当前代码位置

与这条行为直接相关的文件：

- `SystemConfig/system_cfg.h`
- `User/control_task/control_task.c`

关键点：

- `system_cfg.h` 中新增了 `SYSTEM_CFG_ALLOW_HOST_SLAVE_WITHOUT_IBUS`
- `control_task.c` 在 `IBUS` 未连接时，会根据主机命令新鲜度决定是否自动切到 `MODE_REMOTE + SUB_SLAVE`

## 8. 当前权威说明（2026-03-13）

当前默认同时打开：

- `SYSTEM_CFG_ALLOW_HOST_SLAVE_WITHOUT_IBUS = 1`
- `SYSTEM_CFG_HOST_SLAVE_KEEP_DRIVE_POWER = 1`
- `SYSTEM_CFG_READY_KEEP_DRIVE_POWER = 1`

这表示：

- 无论遥控器是否连接，只要进入 `MODE_REMOTE + SUB_SLAVE`，驱动轮都保持上电。
- 上位机会话短暂中断时，不再自动掉电失能。
- `IBUS` 未连接时，只要上位机持续发送新鲜的 `drive/lift` 命令，模式机会自动切到 `MODE_REMOTE + SUB_SLAVE`。

仍然有效的保护：

- 急停始终最高优先级。
- 只有在主机会话仍有效且 `power-policy` 明确要求 disable 时，才会立刻失能。
- `SUB_SLAVE` 的 epoch 保护仍然保留，上位机不能只发一帧旧命令。

- `SystemConfig/system_cfg.h`
- `User/control_task/control_task.c`
- `User/motor_task/motor_task.c`
