# 模块设计文档

## 1. 模块划分总览

| 模块 | 主要文件 | 说明 |
| --- | --- | --- |
| 启动初始化模块 | `main.c`、`freertos.c`、`User_Init.c` | 外设初始化、服务拉起、任务创建 |
| 新协议通信模块 | `uart_task.c`、`uart_stack.c`、`uart_rtos.c`、`host_protocol.c` | UART1 协议栈、会话管理、TLV 编解码 |
| 模式控制模块 | `control_task.c` | 模式机、遥控解析、host 运动命令转换 |
| 电机执行模块 | `motor_task.c`、`bsp_motor_handler.*` | 电机上电、复位、速度/位置控制、关节回零 |
| 遥测模块 | `telemetry_service.c`、`drive_feedback_service` | 真实状态聚合和上传快照生成 |
| CAN 通信模块 | `can_irq_adapter.c`、`can_port.c`、`can_queue.*` | CAN 中断收发、恢复、排队 |
| GPIO 输入模块 | `bsp_gpio_driver.*`、`gpio_port.*` | 急停、上下限位、离散输入采样 |
| 遥控模块 | `ibus_task.c`、`bsp_ibus_handler.*` | IBUS 解析与超时管理 |
| 电池模块 | `battery_task.c`、`bsp_battery_handler.*` | Modbus 轮询、电池状态解析 |
| 显示/灯效模块 | `bsp_handler_display.*`、`ws2812_task.c` | 模式显示与状态灯效 |

## 2. 启动初始化模块

### 2.1 输入

- CubeMX 生成的硬件初始化函数
- `UserAppTask_Init()` 中的应用初始化策略

### 2.2 输出

- 完整运行的 FreeRTOS 任务集
- 新协议 UART1 服务
- 旧串口兼容服务

### 2.3 设计要点

- `UserAppTask_Init()` 先做 `can_queue_init()` 和 `motor_register()`
- 若 UART1 服务初始化失败或任务创建失败，直接停机
- `user_app_task_entry()` 创建完业务任务后自删除，避免占用资源

## 3. 新协议通信模块

### 3.1 `host_protocol`

职责：

- 实现固定帧头 + TLV + CRC16(Modbus) 协议
- 提供帧解析器状态机
- 提供遥测构帧接口

内部状态：

- `ST_FIND_H1`
- `ST_FIND_H2`
- `ST_READ_HDR`
- `ST_READ_PAYLOAD_CRC`

关键特性：

- 支持流式按字节喂入
- 自动跳过帧头前杂波
- 校验版本、长度和 CRC

### 3.2 `uart_stack`

职责：

- 连接 `uart_rtos` 与 `host_protocol`
- 将 RX 字节流转为完整帧回调
- 将上层构帧回调包装为 RTOS 发送接口

### 3.3 `uart_rtos`

职责：

- 创建 UART1 TX/RX 周期任务
- 创建共享 DMA 发送服务任务
- 将裸驱动收发改造成线程上下文调用

设计要点：

- TX 任务按周期构帧，支持“上帧未写完则优先续写”
- RX 任务按周期从 FIFO 批量读字节
- Service 任务通过 `uart_poll_dma_tx()` 驱动 DMA 发送泵

### 3.4 `uart_task`

职责：

- 新协议业务入口
- 会话存活、命令新鲜度维护
- `host_control_cmd_t` mailbox 所有者
- 遥测帧构建者

核心内部状态：

- `last_frame_tick`
- `last_drive_cmd_tick`
- `last_lift_cmd_tick`
- `last_telemetry_tick`
- `tx_seq`
- `latched_status_word`

设计要点：

- 会话超时后清空命令数据面，但保留 `drive_cmd_seq/lift_cmd_seq`
- power/reset 策略使用锁存状态字与掩码更新
- drive、lift、power-policy 三个命令域按域隔离

## 4. 模式控制模块

### 4.1 模块职责

- 每 50ms 更新主模式和子模式
- 每 10ms 执行当前模式
- 将遥控或上位机命令转换为 `robot_motion_cmd_t`
- 管理进入 `SUB_SLAVE` 后的 epoch 捕获

### 4.2 模式来源

- 急停来自 `input_driver_get_status()`
- 遥控模式来自 `IBUS_Handler`
- 上位机命令仅在 `SUB_SLAVE` 下生效

### 4.3 关键机制

- 进入 `SUB_SLAVE` 时，记录当前 `drive_cmd_seq/lift_cmd_seq`
- 只有进入后收到的新命令才允许驱动执行
- 手动关节控制只在 `SUB_MOTOR_CTRL` 且回零未占用时生效
- `SUB_MOTOR_ERR_CLR` 下执行滑台报警复位，并在报警消失后重新使能

### 4.4 数据转换

- host 轮角速度：`mrad/s -> rad/s -> rpm -> 乘减速比`
- host 升降目标：`mm -> 关节绝对位置单位`
- 遥控摇杆：`[-100,100] -> 线速度/角速度 -> 左右轮 rpm`

## 5. 电机执行模块

### 5.1 模块职责

- 统一处理右轮、左轮、关节 3 轴电机
- 处理 motor runtime 的初始化和 ready 流程
- 响应 host power/reset 策略
- 实现关节回零状态机
- 输出真实轮速反馈

### 5.2 驱动轮执行策略

- 先判定是否允许上电
- 未完成 ready 序列前，先走驱动准备流程
- allow_enable 变化时才触发边沿式 enable/disable
- 无命令、急停、host disable 时速度归零

### 5.3 关节执行策略

- 关节回零状态机优先级高于普通位置控制
- 未回零时绝对位置命令无效
- 在 `SUB_SLAVE` 下要同时满足会话 alive 且未被 host disable
- 在 `SUB_MOTOR_CTRL` 下允许手动相对位移
- 在 `SUB_MOTOR_ERR_CLR` 下禁止普通运动命令，只执行滑台错误清除与重新使能

### 5.4 关节回零状态机

状态：

- `IDLE`
- `WAIT_MOTOR`
- `SEEK_LOWER`
- `SETTLE`
- `ZERO`
- `DONE`
- `FAULT`

故障条件：

- 回零超时 `SYSTEM_CFG_JOINT_HOME_TIMEOUT_MS`（按行程估算）
- 相对位置命令下发失败
- 电机进入报警态
- 急停或请求取消时中断

## 6. 遥测模块

### 6.1 `drive_feedback_service`

职责：

- 保存左右轮真实角速度
- 由 `Robot_Speed_Task` 每 10ms 刷新

### 6.2 `telemetry_service`

职责：

- 汇总轮速、关节位置、电池、IBUS、急停、CAN 诊断、电机状态
- 构造 `status_word`、`health_word`、`alarm_info`
- 控制可选遥测字段是否上报

设计要点：

- `status_word` 表示真实 enable / charging 状态
- `health_word` 表示急停、电池通信、IBUS 连接、电机 enable/alarm 等状态
- `alarm_info` 当前由左右轮电机报警码拼装
- `bucket_volume` 默认无效，不上报

## 7. CAN 通信模块

职责：

- 初始化过滤器和中断通知
- 接收中断里抽取标准帧数据
- 将帧转交上层队列或解析入口
- 监测 bus-off、错误码和恢复过程

设计要点：

- `Can_Analy_Task` 中定期调用 `mcu_can_diag_poll_recover()`
- 恢复成功后清除 `recover_pending`
- 遥测中保留一定时间窗口的 CAN 诊断事件

## 8. 辅助模块

### 8.1 GPIO 输入模块

- 每 10ms 更新一次急停与限位状态
- 对外只暴露快照读取接口

### 8.2 电池模块

- 每 2s 下发一次 Modbus 电压查询
- 负责电池通信超时检查

### 8.3 遥控模块

- 默认超时时间 `100ms`
- 周期维护连接状态和通道值

### 8.4 WS2812 灯效模块

- `WS2812_Task` 以 `50ms` 周期刷新灯带，当前 `8` 颗灯按 `4` 个逻辑位置段管理，每段 `2` 颗；默认映射为 `左前、右前、右后、左后`，也可通过 `SYSTEM_CFG_RGB_STRIP_SEGMENT_*` 宏调整。
- `MODE_EMERGENCY` 下整条灯带红灯闪烁，且优先级高于充电显示、普通模式底色和转向灯。
- 电池通信正常且 `charge_status=1` 时，整条灯带显示充电状态：默认红灯，`remain_capacity > 9000` 时切换为绿灯。
- `MODE_READY` 下整条灯带显示紫灯。
- `MODE_REMOTE + SUB_SLAVE` 下整条灯带显示蓝灯，其余 `MODE_REMOTE` 子模式显示绿灯。
- 转向灯仅在 `MODE_REMOTE + SUB_MANUAL/SUB_SLAVE` 下生效，基于当前左右轮指令差速自动判断左右转；左转叠加点亮左前和左后，右转叠加点亮右前和右后，并按固定节拍闪烁。实际物理段顺序由 `SYSTEM_CFG_RGB_STRIP_SEGMENT_*` 宏决定。

## 9. 模块依赖约束

- `uart_task` 不能直接调用电机驱动命令
- `control_task` 不能直接修改 `host_control_cmd_t`
- `motor_task` 不能直接解释 UART TLV
- `telemetry_service` 不负责通信链路调度

## 10. 维护建议

- 所有新增共享状态必须先定义所有者
- 协议新增 Tag 时同步修改 `host_cmd_defs.h` 和接口文档
- 若扩展新执行器，优先复用 `telemetry_service` 的真实状态聚合模式

## 11. 典型改动场景与影响面

这一节专门给接手人员使用。目标不是解释“模块是什么”，而是明确“要改某类需求时应该从哪里下手”。

### 11.1 修改 UART 协议 Tag 或新增一个命令字段

最少要检查这些文件：

| 文件 | 为什么要改 |
| --- | --- |
| `User/communication_task/host_cmd_defs.h` | 增加或修改 Tag 宏 |
| `User/communication_task/uart_task.c` | 解析下行 TLV，更新 mailbox |
| `User/communication_task/host_control_cmd.h` | 若需要持久化命令快照，扩展结构体 |
| `User/control_task/control_task.c` | 若新字段影响控制逻辑，在这里消费 |
| `docs/04_接口文档.md` | 同步更新协议说明 |

建议断点：

- `uart_task_apply_command()`

### 11.2 新增一个遥测字段

最少要检查这些文件：

| 文件 | 为什么要改 |
| --- | --- |
| `User/communication_task/host_cmd_defs.h` | 增加遥测 Tag 宏 |
| `User/communication_task/telemetry_service.h` | 扩展遥测快照结构体 |
| `User/communication_task/telemetry_service.c` | 填充真实值 |
| `User/communication_task/uart_task.c` | 在 `uart_task_build_telemetry_tlv()` 里添加 TLV |
| `docs/04_接口文档.md` | 同步更新遥测定义 |

注意：

- 只有真实数据源可用时才建议上报。
- 不要把 host 意图、默认零值或推测值包装成“真实遥测”。

### 11.3 修改超时策略

最少要检查这些位置：

| 文件 | 参数 |
| --- | --- |
| `User/communication_task/uart_task.c` | 会话超时、drive/lift 新鲜度 |
| `User/communication_task/telemetry_service.c` | CAN 诊断保持窗口 |
| `SystemConfig/system_cfg.h` | CAN 诊断相关宏 |
| `docs/06_配置说明文档.md` | 同步更新配置说明 |

### 11.4 修改模式机语义

最少要检查这些文件：

| 文件 | 为什么要改 |
| --- | --- |
| `User/control_task/robot_mode_service.h` | 枚举定义 |
| `User/control_task/control_task.c` | 模式切换、模式执行 |
| `User/motor_task/motor_task.c` | 某些模式直接影响 allow_enable |
| `User/ws2812_task/ws2812_task.c` | 若灯效要同步变更 |
| `docs/02_软件架构设计文档.md` | 同步更新模式约束 |

### 11.5 修改驱动轮控制算法

优先看：

| 文件 | 关键函数 |
| --- | --- |
| `User/control_task/control_task.c` | `control_task_apply_slave_motion()` |
| `User/control_task/control_task.c` | `manu_set_lr_spd_low()` / `manu_set_lr_spd_high()` |
| `User/motor_task/motor_task.c` | `motor_task_apply_drive_motion()` |
| `SystemConfig/system_cfg.h` | 轮距、轮径、减速比 |

### 11.6 修改关节回零逻辑

优先看：

| 文件 | 关键函数 |
| --- | --- |
| `User/motor_task/motor_task.c` | `motor_task_process_joint_home()` |
| `User/motor_task/motor_task.h` | 回零状态枚举 |
| `BSP_Plantform/Bsp_Drivers/io/driver/bsp_gpio_driver.h` | 限位输入定义 |
| `MCU_Platform/MCU_Core_GPIO/gpio_port.c` | 限位采样极性 |

## 12. 每个模块最重要的“唯一写入口”

接手时一定要先守住下面这张表。很多 bug 都不是算法问题，而是“写错了状态拥有者”。

| 状态 | 唯一写入口 |
| --- | --- |
| `host_control_cmd_t` | `uart_task_apply_command()` |
| `ROBOT_MODE_T` | `control_task_set_mode_main_sub()` / `control_task_set_mode_main()` / `control_task_set_sub_and_speed()` |
| `robot_motion_cmd_t` | `robot_motion_cmd_set_*()` / `robot_motion_cmd_clear_*()` |
| 关节回零状态机 | `motor_task_process_joint_home()` |
| `drive_feedback_t` | `Robot_Speed_Task()` |
| `telemetry_service_snapshot_t` | `telemetry_service_snapshot()` |

原则：

- 如果一个需求让你想绕过这些入口直接写共享状态，通常说明改法不对。

## 13. 建议保留的模块边界

### 13.1 不建议把这些逻辑混在一起

- 不要把 UART 命令解析直接写进 `control_task.c`
- 不要把模式机直接写进 `motor_task.c`
- 不要让 `telemetry_service.c` 反向修改控制状态
- 不要在 ISR 里直接做 TLV 解析或电机控制

### 13.2 推荐保持的结构

- 通信层只产出 `host_control_cmd_t`
- 控制层只产出 `robot_motion_cmd_t`
- 执行层只负责 enable/disable/reset/下发
- 遥测层只负责真实状态汇总

## 14. 接手后的第一轮自检

建议新接手的人第一天做以下 5 个断点验证：

1. 在 `UserAppTask_Init()` 确认任务创建和 UART1 服务正常拉起
2. 在 `uart_task_apply_command()` 确认命令帧能正确落到 mailbox
3. 在 `control_task_apply_slave_motion()` 确认 mailbox 被正确消费
4. 在 `motor_task_apply_drive_motion()` 确认最终速度命令被下发
5. 在 `telemetry_service_snapshot()` 确认上报值来自真实状态

只要这 5 步都走通，后续接手会顺很多。
