# 02 总体设计说明

## 1. 设计目标

当前软件设计目标不是单纯“能跑”，而是建立一条职责清晰、边界可审计、可长期维护的嵌入式控制链路。

核心目标：

- 通信输入、控制决策、执行仲裁、反馈上传彼此解耦
- 上位机命令和真实设备状态分离
- 协议错误、链路错误、状态错误隔离处理
- 形成稳定的 100Hz 端到端控制链

## 2. 分层设计

系统当前按职责分为 5 层。

### 2.1 平台与驱动层

职责：

- STM32F4 USART、DMA、CAN、中断适配
- 基础 UART FIFO / DMA 收发
- 电机驱动、IBUS、电池、显示等 BSP

代表模块：

- `MCU_Platform/MCU_Core_UART/*`
- `MCU_Platform/MCU_Core_IRQ/*`
- `BSP_Plantform/Bsp_Drivers/*`

### 2.2 通信集成层

职责：

- 将 UART1 字节流转换为协议帧
- 周期性构建并发送上行帧
- 启动 UART1 协议服务

代表模块：

- `uart_stack`
- `uart_rtos`
- `bsp_uart_driver`

### 2.3 协议与会话层

职责：

- 协议帧解析与 TLV 编解码
- host mailbox 所有权管理
- 会话活性与命令新鲜度维护
- 协议状态位到内部策略的翻译

代表模块：

- `host_protocol`
- `uart_task`
- `host_cmd_defs.h`
- `host_control_cmd.h`
- `host_status_defs.h`

### 2.4 控制层

职责：

- 模式机
- 遥控输入解释
- 将 host 命令转换为运动快照
- 将手动控制转换为运动快照

代表模块：

- `control_task`
- `robot_mode_service.h`
- `robot_motion_cmd.h`

### 2.5 执行与反馈层

职责：

- 统一裁决驱动轮和关节的使能、失能、复位
- 执行回零状态机
- 下发速度/位置命令
- 汇总真实状态形成上传快照

代表模块：

- `motor_task`
- `drive_feedback_service`
- `telemetry_service`

## 3. 关键状态对象

### 3.1 host mailbox

对象：`host_control_cmd_t`

所有者：`uart_task`

职责：

- 保存最近一次被接受的 host 控制输入
- 保存 drive/lift 的接收序号
- 保存已经解码后的 power/reset 策略

原则：

- 只有通信层写
- 其它层只读快照
- 不保留原始 `status_word`，只保留解码后的策略

### 3.2 模式快照

对象：`ROBOT_MODE_T`

所有者：`control_task`

职责：

- 统一表达主模式、子模式、速度档位
- 给执行层、显示层提供只读模式视图

### 3.3 运动命令快照

对象：`robot_motion_cmd_t`

所有者：`control_task`

职责：

- 表达底盘左右轮 RPM 目标
- 表达关节绝对/相对位置命令

原则：

- 控制层写
- 执行层读
- 不包含 power/reset 真值

### 3.4 驱动反馈快照

对象：`drive_feedback_t`

所有者：`motor_task`

职责：

- 对外提供左右轮真实角速度反馈
- 供 `telemetry_service` 读取

### 3.5 遥测快照

对象：`telemetry_service_snapshot_t`

所有者：`telemetry_service`

职责：

- 汇总真实状态字、健康字、报警、电池、轮速、升降位置
- 决定是否发布可选遥测字段

## 4. 主要任务与周期

| 任务 | 周期 | 职责 |
| --- | --- | --- |
| `ContronlTask` | 10ms | 模式执行、生成运动命令 |
| 模式输入采样 | 50ms | 遥控模式切换与子模式判定 |
| `Motor_Task` | 10ms | 执行仲裁、使能/失能、命令下发 |
| `Robot_Speed_Task` | 10ms | 轮速反馈刷新 |
| `Can_Analy_Task` | 1ms 级轮询 | CAN 维护、通信诊断维护 |
| `uart_task` 发送构帧 | 10ms | 构建 UART1 上行遥测 |
| `uart_task` 接收轮询 | 10ms | 处理 UART1 下行命令 |
| `legacy_rx` | 1ms | 旧串口兼容轮询 |

说明：

- UART1 的线侧收发频率已对齐到 `100Hz`
- host 命令消费、执行下发、速度反馈也已对齐到 `100Hz`
- 模式切换输入采样仍保留为 `50ms`

## 5. 核心数据流

### 5.1 下行控制链

```text
UART1 RX
-> bsp_uart_driver / uart_rtos
-> uart_stack
-> host_protocol
-> uart_task
-> host_control_cmd(mailbox)
-> control_task
-> robot_motion_cmd
-> motor_task
-> bsp_motor_handler
```

### 5.2 上行反馈链

```text
motor_task / battery / ibus / gpio / can diag
-> drive_feedback_service / telemetry_service
-> uart_task
-> host_protocol builder
-> uart_stack
-> UART1 TX
```

## 6. 关键设计约束

### 6.1 单一所有权

- `uart_task` 拥有 host mailbox
- `control_task` 拥有模式状态和运动命令
- `motor_task` 拥有执行仲裁和回零状态机
- `telemetry_service` 拥有上传快照拼装

### 6.2 错误隔离

命令解析按域隔离：

- drive 域错误，只丢 drive
- lift 域错误，只丢 lift
- power-policy 域错误，只丢 power-policy

### 6.3 协议收口

- drive 命令必须左右轮同帧
- 越界命令拒绝，不钳位执行
- 字节序为编译期单一定义
- 无真实数据源的遥测不再伪装成有效值

## 7. 当前设计取舍

### 7.1 READY 模式

当前实现已将 `MODE_READY` 收紧为默认无力矩安全态。是否允许 READY 带电待命，由 `SYSTEM_CFG_READY_KEEP_DRIVE_POWER` 编译期开关决定，默认值为 `0`。

### 7.2 bucket_volume

协议保留 `0x04`，但当前工程未接入真实水量传感器，因此未实现时不上报该 TLV。

### 7.3 旧协议文档差异

历史文档中的 `v_linear / w_angular / ACK` 不再适用当前实现。当前实现以左右轮角速度和无 ACK 为准。
