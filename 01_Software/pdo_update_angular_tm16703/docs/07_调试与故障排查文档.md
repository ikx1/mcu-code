# 调试与故障排查文档

## 1. 调试目标

本文档用于帮助开发和联调人员快速定位以下问题：

- UART1 协议链路不通
- 上位机命令收到了但设备不动作
- 电机不能上电或频繁掉使能
- 关节无法回零或升降不响应
- 遥测异常、状态字不一致
- CAN 总线错误或恢复失败
- 遥控、电池、显示等兼容链路异常

## 2. 推荐排查顺序

建议按以下顺序排查，避免跳层：

1. 物理链路
2. 协议链路
3. 模式状态
4. 命令新鲜度
5. 执行层仲裁
6. 电机运行态
7. 遥测聚合结果

## 3. 关键观测点

### 3.1 通信层

| 观测点 | 接口/位置 | 用途 |
| --- | --- | --- |
| UART1 会话活性 | `uart_session_is_alive()` | 判断最近 1s 是否收到有效帧 |
| drive 新鲜度 | `uart_drive_cmd_is_fresh()` | 判断 drive 命令是否过期 |
| lift 新鲜度 | `uart_lift_cmd_is_fresh()` | 判断 lift 命令是否过期 |
| host mailbox | `host_control_cmd_snapshot()` | 查看通信层最终接受的命令 |
| UART 诊断计数 | `uart_get_diag()` | 查看 FIFO、DMA、丢包、构帧超长情况 |

### 3.2 控制层

| 观测点 | 接口/位置 | 用途 |
| --- | --- | --- |
| 当前模式 | `robot_mode_snapshot()` | 判断是否处于 `MODE_REMOTE + SUB_SLAVE` |
| 运动命令快照 | `robot_motion_cmd_snapshot()` | 判断控制层是否生成了 rpm/关节命令 |
| IBUS 快照 | `ibus_handler_snapshot()` | 判断遥控连接和开关量是否正确 |

### 3.3 执行层

| 观测点 | 接口/位置 | 用途 |
| --- | --- | --- |
| 回零状态机 | `motor_task_joint_home_status_snapshot()` | 判断回零是否在跑、是否 fault |
| 关节是否已回零 | `motor_task_joint_is_homed()` | 判断绝对位置命令是否可执行 |
| 电机运行态 | `motor_runtime_snapshot()` | 判断是否进入 ready/enable/alarm |
| 电机反馈 | `motor_info_snapshot()` | 查看速度、位置、报警码 |

### 3.4 遥测层

| 观测点 | 接口/位置 | 用途 |
| --- | --- | --- |
| 遥测快照 | `telemetry_service_snapshot()` | 查看最终上传值 |
| CAN 诊断 | `mcu_can_diag_snapshot()` | 查看 bus-off、recover 计数 |
| 电池快照 | `BatteryHandler_Snapshot()` | 查看电量和通信故障 |
| GPIO 输入 | `input_driver_get_status()` | 查看急停和限位输入 |

## 4. 典型问题排查

### 4.1 上位机发命令但底盘不动

排查步骤：

1. 确认串口波特率和帧格式正确
2. 确认 `uart_session_is_alive()` 为真
3. 确认 `host_control_cmd_snapshot()` 中左右轮命令已更新
4. 确认 `robot_mode_snapshot()` 为 `MODE_REMOTE + SUB_SLAVE`
5. 确认 `uart_drive_cmd_is_fresh()` 为真
6. 确认 `robot_motion_cmd_snapshot()` 中 rpm 非零
7. 确认驱动轮未被 host disable
8. 确认电机 `MOTOR_STATE_READING` 且非 `MOTOR_STATE_ALARM`

常见原因：

- 左右轮命令没有同帧出现
- 刚切入 `SUB_SLAVE`，但切换后还没收到新命令
- 会话超时导致 mailbox 被清空
- 急停有效
- host power-policy 指定了 disable

### 4.2 升降命令下发了但关节不动作

排查步骤：

1. 确认 `host_control_cmd_snapshot()` 中 `z_lift_mm` 已更新
2. 确认 `uart_lift_cmd_is_fresh()` 为真
3. 确认关节已完成回零：`motor_task_joint_is_homed() == true`
4. 确认回零状态机未占用：`motor_task_joint_home_is_busy() == false`
5. 确认当前模式允许关节动作：
   - `SUB_SLAVE` 下走绝对位置
   - `SUB_MOTOR_CTRL` 下走手动相对位置
6. 确认 `motor_runtime_snapshot(MOTOR_INDEX_JOINT)` 为 `JOINT_ENABLE`

常见原因：

- 升降高度超界，通信层已拒绝
- 关节未回零
- 下限位或上限位状态异常
- host 将关节 power command 置为 disable

### 4.3 关节回零失败

排查重点：

- `motor_task_joint_home_status_snapshot()` 的 `state` 和 `fault`
- `limit_lower` 是否能正确触发
- 电机是否能进入 `JOINT_ENABLE`
- `SYSTEM_CFG_JOINT_HOME_TIMEOUT_MS` 是否按当前行程估算偏短
- `SYSTEM_CFG_JOINT_HOME_EST_SPEED_MM_PER_S` 是否高估了实际回零速度
- 电机是否进入 `JOINT_ALARM`

若回零进入 `FAULT`：

- 先检查限位和总线
- 再确认复位流程是否生效
- 最后检查机械行程是否卡滞

### 4.4 遥测收到了但和主机下发不一致

这是可能的，也是预期行为。

原因：

- 遥测反映真实设备状态，不回显主机意图
- 例如主机要求 enable，但电机未真正上电时，`status_word/health_word` 不会伪造已使能
- `bucket_volume` 当前未接入，默认不上报

### 4.5 UART1 链路偶发丢包或断续

建议检查：

- `uart_get_diag()` 中 `rx_drop_bytes`、`rx_overflow_cnt`
- `tx_dma_start_fail_cnt`、`tx_busy_skip_cnt`
- 主机发送周期是否过密
- DMA2 Stream2/7 中断是否正常触发
- `UART_RX_BUF_SIZE` 和 `UART_DMA_RX_BUF_SIZE` 是否足够

### 4.6 CAN 总线异常

建议检查：

- `mcu_can_diag_snapshot()` 中 `busoff_count`
- `recover_pending` 是否长期为 1
- `recover_fail_count` 是否增长
- 电机节点是否持续报错
- 物理总线、终端电阻、电源是否稳定

## 5. 快速判因表

| 现象 | 优先检查项 |
| --- | --- |
| 完全无遥测 | `USART1`、DMA、CRC、帧格式 |
| 遥测正常但底盘不动 | 模式、drive 新鲜度、host disable、急停 |
| 底盘动但升降不动 | 回零状态、关节 enable、限位 |
| 状态字不符合主机预期 | 真实执行状态 vs 主机意图 |
| 现场一段时间后失联 | 会话超时、上位机周期、UART FIFO 丢包 |
| CAN 总线恢复后仍不稳定 | 供电、终端、电机节点告警 |

## 6. 联调建议

### 6.1 串口联调建议

- 先只验证 `Telemetry(0x01)` 上行
- 再验证只含 `0x03` 的升降命令
- 再验证同时包含 `0x01 + 0x02` 的 drive 命令
- 最后验证 `0x11 + 0x12` 的 power/reset 策略

### 6.2 电机联调建议

- 先不带负载验证 enable/disable
- 再验证低速闭环
- 最后验证极限工况和超时保护

## 7. 调试日志建议

当前工程没有统一日志系统，建议临时增加以下打印或断点：

- `uart_task_apply_command()`
- `control_task_apply_slave_motion()`
- `motor_task_handle_drive_motor()`
- `motor_task_process_joint_home()`
- `telemetry_service_snapshot()`

如果后续要长期维护，建议补充统一事件日志与故障码记录机制。
# 更新说明（2026-03-13）

本页顶部补充当前 `STM32F103VET6` 版本已经验证过的排查结论，后续若与正文中的历史描述冲突，以本节为准。

## 当前版本优先排查项

### 1. 上电后所有功能都不运行

- 先确认 `UserAppTask_Init()` 末尾是否执行了 `vTaskStartScheduler()`
- 当前工程如果调度器无法启动，会进入 `user_init_halt()`

### 2. 程序停在 `vApplicationStackOverflowHook()`

当前代码里可以直接看：

- `g_stack_overflow_task_handle`
- `g_stack_overflow_task_name`

先定位具体任务，再决定是扩栈还是缩减局部栈占用。

### 3. GPIO 与板级映射

- `PE7`：急停，高有效
- `PE8`：上限位，低有效
- `PE9`：下限位，低有效
- `PB0`：`relay1`
- `PB1`：`relay2`

### 4. WS2811/WS2812 现有稳定基线

- `TIM3_CH2(PA7) + DMA1_Channel3`
- `TIM3_ARR_VALUE = 89`
- 整帧 DMA 发送
- 缓冲尾部追加 `64` 个 reset slots

已经验证不稳定的方案：

- 先手动发首 bit，再让 DMA 从第二项开始
- 发送前后切换 `PA7` 的 GPIO 模式强制拉低

如果现场再出现灯带闪烁或第一颗异常，先确认驱动是否被改离了这条基线。

## 6. 当前补充说明（2026-03-13）

### 6.1 导航模式下电机不再自动掉电

当前默认：

- `SYSTEM_CFG_HOST_SLAVE_KEEP_DRIVE_POWER = 1`

因此：

- 进入 `MODE_REMOTE + SUB_SLAVE` 后，驱动轮保持上电。
- 不能再用“主机会话一断就应该自动失能”作为排查前提。

### 6.2 无遥控器时 host 仍可接管底盘

当前默认：

- `SYSTEM_CFG_ALLOW_HOST_SLAVE_WITHOUT_IBUS = 1`

优先检查：

1. `uart_session_is_alive()`
2. `uart_drive_cmd_is_fresh()` 或 `uart_lift_cmd_is_fresh()`
3. `robot_mode_snapshot()` 是否已进入 `MODE_REMOTE + SUB_SLAVE`
4. 上位机是否在切入后持续发送新命令帧

### 6.3 导航模式下何时仍会失能

以下情况仍会掉使能：

- 急停触发。
- 主机会话仍有效，且 `power-policy` 明确要求某个驱动电机 disable。
- 模式退出 `MODE_REMOTE + SUB_SLAVE`。
