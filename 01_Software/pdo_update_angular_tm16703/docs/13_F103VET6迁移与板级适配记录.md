# F103VET6迁移与板级适配记录

## 1. 文档目的

本文档记录 `pdo_update_angular` 从历史版本迁移到 `STM32F103VET6` 后，已经落地并验证过的关键适配项，避免后续再次把旧板卡假设带回当前工程。

## 2. 已完成的关键适配

### 2.1 调度器启动

- 当前工程仍然使用原生 `xTaskCreate()`
- `UserAppTask_Init()` 末尾已补回 `vTaskStartScheduler()`
- 如果调度器启动失败，会进入 `user_init_halt()`

### 2.2 栈溢出定位

`main.c` 中保留以下调试变量：

- `g_stack_overflow_task_handle`
- `g_stack_overflow_task_name`

如果再次进入 `vApplicationStackOverflowHook()`，直接读取这两个变量即可定位具体任务。

### 2.3 GPIO 与控制输入

当前已确认板级输入：

- `PE7`：急停，高有效
- `PE8`：上限位，低有效
- `PE9`：下限位，低有效

当前已确认输出：

- `PB0`：`relay1`
- `PB1`：`relay2`
- `PE15`：电池 `RS485` 方向脚
- `PE14`：超声波 `RS485` 方向脚

### 2.4 WS2811/WS2812 稳定方案

当前稳定方案已经固定为：

- `TIM3_CH2(PA7) + DMA1_Channel3`
- `TIM3_ARR_VALUE = 89`
- 整帧 DMA 发送
- 缓冲尾部追加 `64` 个 reset slots

已经确认不稳定的方案：

- 手动先发首 bit，再让 DMA 从第二个数据开始
- 在发送前后把 `PA7` 在 `AF_PP` 和普通 GPIO 模式之间切换

### 2.5 无遥控器时的上位机接管

当前已经增加显式配置：

- `SYSTEM_CFG_ALLOW_HOST_SLAVE_WITHOUT_IBUS = 1`

行为约束如下：

- `IBUS` 未连接时，只要上位机持续发送新鲜的 drive/lift 命令，模式机会自动切到 `MODE_REMOTE + SUB_SLAVE`
- 急停仍然保持最高优先级
- 若上位机命令超时，系统仍会回到 `MODE_READY`
- `SUB_SLAVE` 仍保留原来的 epoch 保护，因此切入后需要继续收到新的命令帧，底盘才会真正开始运动

## 5. 后续维护注意事项

1. 不要再把旧 `F429` 版本的 `TIM3_CH3(PB0)` 描述带回当前工程。
2. 不要把 `PB0/PB1` 再复用为历史灯带或其它遗留功能。
3. 如果后续启用新的 DMA 外设，先确认不会占用 `DMA1_Channel3`。
4. 如果修改限位极性或引脚，必须同时更新代码和本文档。
