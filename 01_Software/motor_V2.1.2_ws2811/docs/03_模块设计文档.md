# 03 模块设计文档

> 文档状态：当前权威文档
> 适用基线：STM32F429ZET6 + HAL/LL + FreeRTOS(CMSIS-RTOS v2)
> 对应工程：motor_V2.1.1_ws2811
> 说明：本文档按模块说明职责、输入输出、关键函数和修改注意点

## 1. 模块划分原则

当前工程的模块划分不是按“文件类型”来分，而是按职责来分：

- 启动与任务初始化
- UART1 主机通信
- 控制层模式机
- 执行层电机与关节
- 反馈与遥测
- CAN 与驱动状态解析
- 外设辅助模块

阅读或修改时，优先先判断自己改的是哪一类职责，再进入对应模块，不要跨层散改。

## 2. 启动与任务初始化模块

### 2.1 位置

- `Core/Src/main.c`
- `User/User_Init/User_Init.c`

### 2.2 职责

- 初始化底层外设
- 初始化共享服务
- 创建应用任务
- 启动 FreeRTOS 调度器

### 2.3 关键函数

| 函数 | 作用 |
| --- | --- |
| `main()` | 程序入口，初始化 GPIO/UART/CAN/TIM 等基础外设 |
| `UserAppTask_Init()` | 初始化 CAN 队列、电机对象、UART1 服务、传统串口桥接，并启动调度器 |
| `user_app_task_entry()` | 创建业务任务后删除自身 |

### 2.4 修改注意点

- 不要把业务逻辑塞进 `main()`
- 不要绕过 `UserAppTask_Init()` 单独创建任务
- 修改任务优先级和创建顺序时，要重新检查控制层和执行层依赖

## 3. UART1 主机通信模块

### 3.1 位置

- `User/communication_task/uart_task.c`
- `BSP_Plantform/Bsp_Integration/uart/uart_stack.c`
- `BSP_Plantform/Bsp_Integration/uart/uart_rtos.c`
- `BSP_Plantform/Bsp_Drivers/communication/driver/bsp_uart_driver.c`
- `Middlewares/components/host_protocol/host_protocol.c`
- `MCU_Platform/MCU_Core_UART/*`

### 3.2 职责

- 接收 UART1 字节流
- 解析协议帧和 TLV
- 维护主机 session 和命令 freshness
- 写入 `host_control_cmd_t`
- 生成 telemetry 帧并发送

### 3.3 关键函数

| 函数 | 作用 |
| --- | --- |
| `uart_task_start()` | 启动 UART1 协议服务 |
| `uart_task_apply_command()` | 将命令帧解析为 mailbox 更新 |
| `uart_task_build_telemetry_frame()` | 组 telemetry 帧 |
| `uart_parser_feed()` | 流式解析帧 |
| `uart_builder_begin/end()` | 打包协议帧 |
| `uart_rtos_start()` | 创建 UART TX/RX 任务 |
| `uart_device_init()` | 初始化 UART FIFO 和 DMA 运行时 |

### 3.4 输入与输出

输入：

- USART1 DMA 接收到的原始字节流
- 主机下发的 TLV 命令帧

输出：

- `host_control_cmd_t`
- UART1 telemetry 字节流

### 3.5 修改注意点

- 改协议字段时，先改 `host_cmd_defs.h` 和 `uart_task.c`
- 不要让通信层直接操作电机
- 不要把 telemetry 改成回显主机意图

## 4. 控制层模块

### 4.1 位置

- `User/control_task/control_task.c`
- `User/control_task/robot_mode_service.h`
- `User/control_task/robot_motion_cmd.h`

### 4.2 职责

- 决定当前主模式和子模式
- 解析遥控输入与主机命令来源
- 生成统一的 `robot_motion_cmd_t`
- 维护显示层使用的模式状态

### 4.3 关键函数

| 函数 | 作用 |
| --- | --- |
| `ContronlTask()` | 控制层主循环 |
| `robot_mode_update_50ms()` | 模式机更新 |
| `robot_state_execute()` | 根据当前模式执行相应控制分支 |
| `control_task_apply_slave_motion()` | 主机命令转运动意图 |
| `control_task_apply_manual_joint_motion()` | 手动关节控制 |
| `robot_mode_snapshot()` | 快照当前模式 |
| `robot_motion_cmd_snapshot()` | 快照当前运动意图 |

### 4.4 输入与输出

输入：

- `input_status_t`
- `IBUS_Handler`
- `host_control_cmd_t`

输出：

- `ROBOT_MODE_T`
- `robot_motion_cmd_t`

### 4.5 修改注意点

- 控制层只负责“决定想做什么”，不负责最终执行
- 模式变化会影响灯带、显示和执行策略，不能只改一处
- 新增模式时必须同时检查 `control_task`、`ws2812_task` 和 `motor_task`

## 5. 执行层模块

### 5.1 位置

- `User/motor_task/motor_task.c`
- `User/motor_task/motor_task.h`

### 5.2 职责

- 电机初始化与 ready 序列管理
- reset、enable、disable、speed、position 的最终裁决
- 关节回零状态机
- 故障清除与 power hold 策略

### 5.3 关键函数

| 函数 | 作用 |
| --- | --- |
| `Motor_Task()` | 执行层主循环 |
| `motor_task_apply_reset_edges()` | 处理主机 reset 位边沿 |
| `motor_task_handle_drive_motor()` | 左右轮上电和状态机维护 |
| `motor_task_apply_drive_motion()` | 左右轮速度下发 |
| `motor_task_handle_joint_motor()` | 关节上电、回零、故障清除 |
| `motor_task_process_joint_home()` | 回零状态机 |
| `motor_task_apply_joint_motion()` | 关节动作执行 |

### 5.4 输入与输出

输入：

- `robot_motion_cmd_t`
- `host_control_cmd_t`
- `input_status_t`
- `motor_info_t`

输出：

- 电机驱动指令
- 关节回零状态
- `drive_feedback_t`

### 5.5 修改注意点

- 关节回零逻辑集中在本模块，不要分散到控制层
- 调整 power policy 时，优先改 allow 函数，不要到处加特判
- 执行层是安全闸门，任何“为了方便直接动电机”的改法都要非常谨慎
- `SUB_MOTOR_ERR_CLR` 和主机 reset 位当前都允许驱动轮进入清错路径，改这条链路时必须同时回归“报警清除后重新使能”
- 关节手动点动当前由控制层直接下发相对位置，但仍必须受上/下限位保护，不要为了调试去掉限位裁决

## 6. 反馈与遥测模块

### 6.1 位置

- `User/motor_task/drive_feedback_service.h`
- `User/communication_task/telemetry_service.c`
- `User/communication_task/telemetry_service.h`

### 6.2 职责

- 从驱动反馈中提取真实轮速
- 聚合电池、遥控、GPIO、电机、CAN 诊断等状态
- 生成统一的 telemetry snapshot

### 6.3 关键函数

| 函数 | 作用 |
| --- | --- |
| `Robot_Speed_Task()` | 生成真实轮速反馈 |
| `drive_feedback_snapshot()` | 提供真实轮速快照 |
| `telemetry_service_snapshot()` | 聚合真实状态 |
| `telemetry_service_diag_maintenance()` | 维护 CAN 诊断保持窗口 |

### 6.4 修改注意点

- 遥测层不要写入控制意图
- 新增遥测字段时，优先从真实生产者取值，不要直接复用命令值
- `bucket_volume` 当前仍是预留字段，不要假装有真实来源
- `telemetry_service_diag_maintenance()` 当前维护的是 CAN 诊断 sticky 窗口；稳定期结束后会重置窗口基线，不再直接清底层 producer 计数

## 7. CAN 与电机驱动模块

### 7.1 位置

- `Middlewares/components/can_queue/can_queue.c`
- `MCU_Platform/MCU_Core_CAN/can_irq_adapter.c`
- `MCU_Platform/MCU_Core_CAN/can_port.c`
- `BSP_Plantform/Bsp_Drivers/motor/handler/bsp_motor_handler.c`

### 7.2 职责

- 处理 CAN 收发和 bus-off 恢复
- 维护 TX 队列和 RX FIFO
- 解析左右轮和关节的 PDO/SDO 数据
- 更新 `motor_info_t` 和运行时状态

### 7.3 关键函数

| 函数 | 作用 |
| --- | --- |
| `can_queue_init()` | 初始化 CAN 队列和 IRQ hooks |
| `mcu_can_diag_poll_recover()` | 轮询 bus-off 恢复 |
| `can_poll_parse_loop()` | 解析 RX FIFO 中的 CAN 帧 |
| `motor_register()` | 注册三路电机对象 |
| `ican_rec_analyse()` | 按标准帧 ID 分发给目标电机 |

### 7.4 修改注意点

- 解析电机帧时，先确认电机的 PDO 布局，不要混用轮驱动和关节布局
- CAN 错误恢复和业务控制已耦合到 `Can_Analy_Task()`，改这里要检查调试和遥测链路

## 8. 输入与辅助外设模块

### 8.1 IO / 急停限位

位置：

- `User/io_task/io_task.c`
- `BSP_Plantform/Bsp_Drivers/io/driver/bsp_gpio_driver.c`
- `MCU_Platform/MCU_Core_GPIO/gpio_port.c`

职责：

- 周期采集急停和限位输入
- 提供 `input_status_t` 给控制层和执行层使用

### 8.2 IBUS

位置：

- `User/ibus_task/ibus_task.c`
- `BSP_Plantform/Bsp_Drivers/ibus/handler/bsp_ibus_handler.c`

职责：

- 解析遥控通道值
- 判断连接超时
- 提供模式机和手动控制输入

### 8.3 Battery

位置：

- `User/battery_task/battery_task.c`
- `BSP_Plantform/Bsp_Drivers/battery/handler/bsp_battery_handler.c`

职责：

- 周期查询电池数据
- 维护电池通信故障状态
- 提供 SOC、电压、电流和充电状态

### 8.4 Display

位置：

- `BSP_Plantform/Bsp_Drivers/display/handler/bsp_handler_display.c`

职责：

- 处理显示屏请求
- 按当前模式和电池状态返回显示数据

### 8.5 WS2812 / WS2811

位置：

- `User/ws2812_task/ws2812_task.c`
- `BSP_Plantform/Bsp_Drivers/ws2812/driver/bsp_ws2812_driver.c`

职责：

- 按模式、转向、电池充电状态驱动 RGB 灯带表现

## 9. 模块协作时的三条规则

1. 共享状态对象尽量只有一个写入口
2. 控制层和执行层职责不能混
3. 现场状态展示必须基于真实状态，而不是命令值

## 10. 修改入口建议

| 修改目标 | 首选模块 |
| --- | --- |
| 协议字段 | `uart_task`, `host_cmd_defs`, `telemetry_service` |
| 模式机 | `control_task` |
| 电机上电策略 | `motor_task` |
| 回零逻辑 | `motor_task` + `system_cfg.h` + `gpio_port.c` |
| 遥测内容 | `telemetry_service` |
| 灯带表现 | `ws2812_task` |
| 遥控映射 | `bsp_ibus_handler` + `control_task` |
