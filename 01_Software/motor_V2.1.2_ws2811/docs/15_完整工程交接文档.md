# 15 完整工程交接文档

> 文档状态：当前权威文档
> 适用基线：STM32F429ZET6 + HAL/LL + FreeRTOS(CMSIS-RTOS v2)
> 对应工程：motor_V2.1.1_ws2811
> 说明：本文档是一份面向交接和快速上手的总册，如与源码冲突，以当前源码为准

## 1. 当前工程基线

| 项目 | 当前基线 |
| --- | --- |
| 工程目录 | `motor_V2.1.1_ws2811/` |
| MCU | `STM32F429ZET6` |
| 工程文件 | `MDK-ARM/Car_Control.uvprojx` |
| 软件栈 | `HAL + LL + FreeRTOS(CMSIS-RTOS v2)` |
| 主机通信主链路 | `USART1 + DMA2_Stream2/7 + UART1 新协议栈` |
| 遥控输入 | `UART4 + IBUS` |
| 电池链路 | `USART3 + Modbus` |
| 显示链路 | `USART2` |
| 灯带链路 | `TIM3_CH3(PB0) + DMA1_Stream7` |
| 启动方式 | `main() -> osKernelInitialize() -> MX_FREERTOS_Init() -> UserAppTask_Init() -> osKernelStart()` |

## 2. 核心心智模型

```text
主机 UART1 命令 或 遥控 IBUS 输入
    -> 控制层选择模式并生成运动意图
    -> 执行层决定是否允许上电/运动/回零
    -> CAN 驱动执行
    -> 真实反馈被聚合
    -> 遥测/显示/灯带对外呈现状态
```

必须牢记：通信层不直接驱动电机，控制层不直接写 CAN，执行层保留最终安全裁决权，遥测层只上传真实状态。

## 3. 启动流程与任务拓扑

### 3.1 启动流程

1. `HAL_Init()`
2. `SystemClock_Config()`
3. 初始化 GPIO、DMA、CAN、USART1、UART4、USART3、USART2、TIM3
4. `osKernelInitialize()`
5. `MX_FREERTOS_Init()`
6. `UserAppTask_Init()` 中完成 CAN 队列、电机对象、UART1 服务和旧串口桥接初始化
7. `osKernelStart()`

### 3.2 业务任务

- `ScramTask`
- `ContronlTask`
- `Motor_Task`
- `Can_Analy_Task`
- `Robot_Speed_Task`
- `user_legacy_rx_service_task`
- `ibusTask`
- `ModbusTask`
- `WS2812_Task`
- `UART_TX / UART_RX / UART_DMA_SVC`

## 4. 四条主链路

### 4.1 主机命令链路

```text
USART1 IRQ / DMA -> uart_irq_adapter -> bsp_uart_driver -> uart_rtos
-> uart_stack -> host_protocol -> uart_task -> host_control_cmd_t
-> control_task -> motor_task
```

### 4.2 遥控输入链路

```text
UART4 IRQ -> serial_irq_router -> ibus_driver_input_byte()
-> ibus_handler -> control_task
```

### 4.3 电机反馈链路

```text
CAN IRQ -> can_queue -> can_poll_parse_loop -> bsp_motor_handler
-> motor_info / motor_runtime -> Robot_Speed_Task / telemetry_service
```

### 4.4 状态呈现链路

```text
telemetry_service -> UART1 telemetry
bsp_handler_display -> USART2
WS2812_Task -> WS2811 灯带显示
```

## 5. UART1 新协议栈

当前只使用两类帧：

- `Telemetry = 0x01`
- `Command = 0x81`

左右轮命令必须同帧同时出现，单位为 `mrad/s`。协议栈模块包括：

- `bsp_uart_driver.c`
- `uart_rtos.c`
- `uart_stack.c`
- `host_protocol.c`
- `uart_task.c`

## 6. 控制层与执行层

### 6.1 控制层

`control_task.c` 负责：

- 模式机切换
- 根据 IBUS 或主机命令生成 `robot_motion_cmd_t`
- 对 `SUB_SLAVE` 新命令做 freshness 和 epoch 保护

### 6.2 执行层

`motor_task.c` 负责：

- 三路电机上电/使能/关闭
- 左右轮速度命令下发
- 关节回零、绝对位置和手动点动控制
- 急停、未使能、未回零、故障等安全拦截

## 7. 灯带实现

当前工程灯带仍维持 `WS2811` 实现口径：

- 业务逻辑在 `User/ws2812_task/ws2812_task.c`
- 驱动层在 `bsp_ws2812_driver.c/.h`
- 板级资源是 `PB0 + TIM3_CH3 + DMA1_Stream7`
- 默认逻辑 LED 数量是 `8`

现场表现包括：

- 急停红灯闪烁
- READY 紫色
- REMOTE + SUB_SLAVE 蓝色
- 其他 REMOTE 绿色
- 左右转向橙色闪烁

## 8. 关键配置项

最关键的配置入口在 `SystemConfig/system_cfg.h`：

- `SYSTEM_CFG_ENABLE_DEBUG = 1`
- `SYSTEM_CFG_READY_KEEP_DRIVE_POWER = 1`
- `SYSTEM_CFG_ALLOW_HOST_SLAVE_WITHOUT_IBUS = 1`
- `SYSTEM_CFG_HOST_SLAVE_KEEP_DRIVE_POWER = 1`
- `SYSTEM_CFG_JOINT_AUTO_HOME_ON_BOOT = 1`
- `SYSTEM_CFG_RGB_STRIP_LED_NUM = 8`

同时还要联动检查：

- `bsp_uart_driver.h`
- `host_cmd_defs.h`
- `host_protocol.h`

## 9. 常见排障入口

### 9.1 主机发了命令但车不动

1. 看 `UART_RX` 是否收到了完整帧
2. 看 `host_control_cmd_t` 是否刷新
3. 看 `robot_mode` 是否进入 `MODE_REMOTE + SUB_SLAVE`
4. 看 `motor_task` 是否因急停、未使能、未回零或 fault 拦截

### 9.2 遥控器没反应

1. 看 `UART4_IRQHandler()` 是否进中断
2. 看 `ibus_driver_input_byte()` 是否持续收字节
3. 看 `ibusTask` 是否判定超时
4. 看 `control_task` 是否正确更新模式

### 9.3 灯带异常

1. 看 `WS2812_Task` 是否运行
2. 看 `system_cfg.h` 中四段映射
3. 看 `PB0 + TIM3_CH3 + DMA1_Stream7` 是否被改动
4. 看 `bsp_ws2812_driver.h` 的时序参数是否被破坏

## 11. 交接时必须强调的结论

- 当前工程是 `STM32F429ZET6 + HAL/LL + FreeRTOS(CMSIS-RTOS v2)` 基线
- `freertos.c` 负责外层调度骨架，`UserAppTask_Init()` 负责业务系统起步
- `USART2` 是显示，`UART4` 是 IBUS，不能按 F103 工程的串口分配理解
- 当前灯带仍是 `WS2811` 实现，不是 `SM16703/TM16703` 口径
- 控制层生成意图，执行层保留最终安全裁决权
