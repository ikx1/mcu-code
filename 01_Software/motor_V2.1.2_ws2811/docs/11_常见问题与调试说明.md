# 11 常见问题与调试说明

> 文档状态：当前权威文档
> 适用基线：STM32F429ZET6 + HAL/LL + FreeRTOS(CMSIS-RTOS v2)
> 对应工程：motor_V2.1.1_ws2811
> 说明：本文档面向现场和联调，给出高频问题的短平快判断方法

## 1. 主机发命令了，为什么车不动？

先看四件事：

1. 当前是不是 `MODE_REMOTE + SUB_SLAVE`
2. `uart_drive_cmd_is_fresh()` 是不是真
3. 急停是否触发
4. 电机是否被 force disable 或尚未 ready

## 2. 刚切到 `SUB_SLAVE`，为什么之前那帧命令不继续执行？

这是当前设计要求。进入 `SUB_SLAVE` 后必须收到切换后的新命令，旧命令不会继续生效，用来避免模式切换时误动作。

## 3. 主机发了升降命令，为什么关节不动？

最常见原因：

- 关节还没回零
- 关节正在回零
- 当前模式不允许关节动作
- 关节被 disable
- lift 命令已不 fresh

## 4. READY 模式下驱动还上电，是不是 bug？

不一定。当前默认 `SYSTEM_CFG_READY_KEEP_DRIVE_POWER = 1`，READY 模式可以保持驱动上电。

## 5. 没有遥控器，为什么上位机还能接管？

当前默认 `SYSTEM_CFG_ALLOW_HOST_SLAVE_WITHOUT_IBUS = 1`。只要主机 session 和命令 freshness 满足，就可以进入 `SUB_SLAVE`。

## 6. telemetry 为什么和命令值不一致？

因为 telemetry 发的是实际状态，不是主机命令回显。执行层如果拦截了命令，遥测会反映“没执行”而不是“收到命令”。

## 7. 状态字里 enable 没变，是不是没收到命令？

不一定。可能是：

- 收到命令了，但执行层没允许动作
- 电机还未进入相应状态
- 主机只是表达了意图，真实状态尚未变化

## 8. UART1 有波形，为什么系统还是不认帧？

优先检查：

- 协议头是否为 `0xA0 0x0A`
- `VER` 是否正确
- `LEN` 是否正确
- `CRC16(Modbus)` 是否正确
- 左右轮 TLV 是否成对

## 9. CAN 有收包，为什么轮速还是不更新？

优先检查：

- 收到的是不是目标电机节点
- PDO/SDO 布局是否匹配
- `ican_rec_analyse()` 是否命中对应电机
- `Robot_Speed_Task()` 是否正常运行

## 10. 关节回零为什么会进 fault？

高频原因：

- 下限位没触发
- 限位极性配置错
- 驱动报警
- 回零超时参数不合理
- `reset_zero` 失败

## 11. 灯带方向不对，应该改哪里？

优先改 `system_cfg.h` 中的 RGB 段映射和每段 LED 范围，不要先改业务逻辑。

## 12. 导航模式下转向灯会亮吗？

会。当前 `MODE_REMOTE + SUB_SLAVE` 和 `MODE_REMOTE + SUB_MANUAL` 都会根据左右轮命令差叠加转向灯；如果两侧轮速都太低，转向灯不会亮。

## 13. 电机报警后怎么清？

当前有两条主路径：

- 进入 `SUB_MOTOR_ERR_CLR`
- 上位机在有效 session 下发送 reset 位

注意：清错成功后驱动还需要重新走使能序列，所以“报警消失”和“重新能转”不是同一个时刻。

## 14. 手动升降到限位为什么不动？

这是当前保护逻辑。手动点动碰到上限位时不会继续上行，碰到下限位时不会继续下行，超限方向会被直接夹成 `0`。

## 15. 我想改上位机协议，先改哪里？

顺序建议：

1. `host_cmd_defs.h`
2. `uart_task.c`
3. `host_control_cmd.h`
4. `telemetry_service.c`
5. 再检查主机端实现

## 16. 我想改控制模式，先改哪里？

优先改：

- `control_task.c`
- `robot_mode_service.h`
- 再联查 `motor_task.c`、`ws2812_task.c`、显示逻辑

## 17. 我想查“问题到底在哪一层”，怎么最快？

按这个顺序看：

1. `host_control_cmd_t`
2. `ROBOT_MODE_T`
3. `robot_motion_cmd_t`
4. `input_status_t`
5. `motor_info_t`
6. `telemetry_service_snapshot_t`

看完这六个对象，通常就能判断问题在通信、控制、执行还是反馈。
