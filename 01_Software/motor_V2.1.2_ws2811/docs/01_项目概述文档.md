# 01 项目概述文档

> 文档状态：当前权威文档
> 适用基线：STM32F429ZET6 + HAL/LL + FreeRTOS(CMSIS-RTOS v2)
> 对应工程：motor_V2.1.1_ws2811
> 说明：本文档用于建立对项目目标、系统组成和运行边界的整体认知

## 1. 项目简介

本工程是一个面向移动底盘与升降执行机构的控制固件工程，运行在 `STM32F429ZET6` 上，负责完成以下任务：

- 接收上位机通过 UART1 下发的运动与策略命令
- 接收遥控器通过 IBUS 下发的手动控制输入
- 通过 CAN 总线驱动左右轮电机和升降关节电机
- 采集急停、限位、电池、驱动反馈等状态
- 将真实状态通过 UART1 遥测回传
- 通过显示屏和灯带呈现当前运行状态

从系统定位上看，这不是一个单纯的串口通信工程，也不是一个单纯的电机驱动工程，而是一套包含通信、模式管理、运动控制、执行裁决、状态回传的完整嵌入式控制软件。

## 3. 系统对外能力

### 3.1 上位机能力

当前系统支持上位机通过 UART1 完成以下能力：

- 下发左右轮角速度命令
- 下发关节升降高度命令
- 下发 power/reset 策略位
- 接收底盘真实轮速、关节位置、电池状态、健康状态、报警状态等遥测

### 3.2 遥控能力

当前系统支持通过 IBUS 实现：

- 模式切换
- 手动行驶控制
- 手动关节控制
- 充电、从机控制、故障清除等子模式切换

### 3.3 执行能力

系统当前控制的执行对象有：

- 右轮驱动电机
- 左轮驱动电机
- 升降关节电机

### 3.4 状态呈现能力

系统当前支持以下状态呈现方式：

- UART1 遥测上报
- USART2 显示屏数据回包
- RGB 灯带状态展示

## 4. 工程的核心设计思路

### 4.1 统一的控制主线

本工程的主控制链路可以概括为：

```text
输入源（主机/遥控）
-> 控制层生成运动意图
-> 执行层裁决是否允许动作
-> 驱动层通过 CAN 执行
-> 反馈层汇总真实状态
-> 输出层回传和显示
```

其中每一层都有明确职责：

- 通信层只负责收发和命令落地
- 控制层只负责模式与意图生成
- 执行层负责真正的安全裁决和动作下发
- 遥测层负责对外呈现真实状态

### 4.2 为什么这套分层重要

这套分层让系统具备以下优点：

- 修改协议时，不必直接改电机执行逻辑
- 修改模式机时，不必直接改串口驱动
- 主机命令和遥控输入最终都落到统一执行路径
- 真实状态与控制意图可以明确区分，避免联调误判

## 5. 当前工程的关键运行规则

### 5.1 主机命令不是直接动作

UART1 收到命令后，并不会直接驱动电机，而是写入 `host_control_cmd_t`。真正动作要等控制层和执行层共同确认。

### 5.2 左右轮命令必须同帧出现

当前协议约束左右轮角速度必须在同一帧同时下发，系统不接受单轮独立驱动命令。

### 5.3 主机模式切入后必须收到新命令才能运动

进入 `SUB_SLAVE` 后，系统会记录当前命令序号，要求后续必须收到一帧新的 fresh 命令才能真正运动，以防旧命令误动作。

### 5.4 遥测只发真实状态

上位机看到的遥测不是“系统想做什么”，而是“系统实际做了什么”。

### 5.5 关节动作依赖回零状态

关节没有完成回零时，主机下发的绝对高度命令不会直接生效。

## 7. 项目运行场景

### 7.1 正常遥控场景

遥控器连接正常时：

- 控制层进入 `MODE_REMOTE`
- 根据开关选择 `SUB_MANUAL`、`SUB_SLAVE`、`SUB_CHARGE`、`SUB_MOTOR_CTRL`、`SUB_MOTOR_ERR_CLR`
- 手动驾驶和手动关节控制直接走遥控路径

### 7.2 上位机接管场景

当配置允许且 UART1 会话活跃时，即使没有 IBUS，系统也可以由主机接管进入 `SUB_SLAVE`。

### 7.3 急停场景

急停触发后：

- 模式转入 `MODE_EMERGENCY`
- 执行层停止运动
- 遥测和状态显示反映当前故障状态

### 7.4 关节回零场景

上电后如果配置开启自动回零，执行层会在满足条件时自动启动关节回零状态机，直到成功、失败或被打断。

## 8. 当前工程的边界与限制

- 当前没有完整的自动化测试框架
- 当前 UART1 协议只覆盖既定控制和遥测字段，没有 ACK 帧链路
- `UART8` 超声波链路仍是预留状态
- 料斗容积等辅助状态当前没有接入真实传感器
- `docs/` 中仍保留历史资料，阅读时必须区分权威和历史背景
