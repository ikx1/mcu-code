# 08 测试文档

> 文档状态：当前权威文档
> 适用基线：STM32F429ZET6 + HAL/LL + FreeRTOS(CMSIS-RTOS v2)
> 对应工程：motor_V2.1.1_ws2811
> 说明：当前工程暂无完善自动化测试框架，本文档以手工验证项、联调检查项和建议测试项为主

## 1. 当前测试现状

当前仓库内没有成熟的完整测试框架，但已经补入少量主机侧回归测试，工程验证主要依赖：

- Keil 工程编译通过
- 板级联调验证
- 断点观察关键状态对象
- 主机、遥控、CAN、电池等真实链路联调
- `tests/test_motor_task_err_clear.c`
- `tests/test_control_task_joint_limit.c`
- `tests/test_telemetry_service_diag.c`

当前这几组主机回归覆盖：

- 驱动轮报警清除和重新使能
- 手动关节点动的上下限位保护
- CAN 诊断 sticky 窗口在自动清窗边界上的新故障保留

因此，本文档仍不宣称已有完善自动化覆盖，而是整理“当前至少应验证什么”。

## 2. 最小回归验证清单

每次修改协议、模式机、执行层或回零逻辑后，至少完成以下检查：

### 2.1 启动与任务基础检查

- 工程可编译通过
- 系统上电后可进入调度器
- `ContronlTask`、`Motor_Task`、`Can_Analy_Task` 正常运行
- `uart_task_start()` 成功启动

### 2.2 UART1 协议链路检查

- 上位机可向 UART1 发送一帧合法 command
- `uart_task_apply_command()` 能命中断点
- `host_control_cmd_t` 被更新
- 设备能按周期返回 telemetry 帧

### 2.3 模式机检查

- 急停触发时进入 `MODE_EMERGENCY`
- IBUS 正常时可进入 `MODE_REMOTE`
- 无 IBUS 且配置允许时，上位机可接管进入 `SUB_SLAVE`
- 子模式切换不会留下旧运动命令残留

### 2.4 驱动执行检查

- 主机 drive 命令可驱动左右轮
- 主机 lift 命令在回零完成后可驱动关节
- force disable 时相应电机不动作
- reset 边沿能触发一次性 reset 动作
- `SUB_MOTOR_ERR_CLR` 下驱动报警可进入复位路径
- 驱动报警清除后可重新进入使能序列

### 2.5 回零检查

- 上电自动回零时，状态机能完整走完或正确进入 fault
- 下限位触发后可进入 settle 和 zero 阶段
- 回零完成后 `motor_task_joint_is_homed()` 为真
- 手动点动触碰上/下限位时，超限方向应被抑制为 `0`

### 2.6 遥测检查

- 左右轮遥测速率和实测运动方向一致
- 电池 SOC、充电状态、急停状态可反映到 telemetry
- `status_word` 和 `health_word` 含义正确
- CAN 诊断稳定窗口到期后会重置 sticky 基线，但新 fault 不应在清窗边界被吞掉

## 3. 建议的手工联调用例

### 用例 1：UART1 收包主线

目标：确认主机命令可以进入控制链路。

步骤：

1. 启动系统
2. 发送一帧合法 `Command(0x81)`
3. 观察 `uart_task_apply_command()`
4. 检查 `host_control_cmd_t` 对应字段

预期：

- 命令字段被正确解析
- `uart_session_is_alive()` 为真

### 用例 2：主机驱动控制主线

目标：确认主机 drive 命令能最终触发电机执行。

步骤：

1. 保证系统可进入 `MODE_REMOTE + SUB_SLAVE`
2. 连续发送左右轮速度命令
3. 观察 `control_task_apply_slave_motion()`
4. 观察 `motor_task_apply_drive_motion()`

预期：

- `robot_motion_cmd_t` 中左右轮 RPM 非零
- 执行层调用 `motor_cmd_set_speed()`

### 用例 3：主机关节控制主线

目标：确认主机 lift 命令在回零完成后生效。

步骤：

1. 确认关节已回零
2. 连续发送 `0x03` 升降命令
3. 观察 `control_task_apply_slave_motion()`
4. 观察 `motor_task_apply_joint_motion()`

预期：

- 关节绝对位置命令被下发
- 未回零时应被阻止，回零后才动作

### 用例 4：急停保护

目标：确认急停优先级最高。

步骤：

1. 下发可运动命令
2. 触发急停输入
3. 观察模式与执行层行为

预期：

- 切入 `MODE_EMERGENCY`
- 驱动速度被清零
- 遥测和灯带反映急停状态

### 用例 5：无 IBUS 主机接管

目标：确认当前配置下无遥控器主机仍可接管。

步骤：

1. 断开 IBUS
2. 持续发送 fresh drive 或 lift 命令
3. 观察模式机

预期：

- 进入 `MODE_REMOTE + SUB_SLAVE`
- 不需要遥控器也可形成主机控制链路

## 4. 建议的专项验证项

### 4.1 配置改动后验证

| 改动类型 | 至少验证内容 |
| --- | --- |
| 改 `SYSTEM_CFG_READY_KEEP_DRIVE_POWER` | READY 模式是否保留驱动上电 |
| 改 `SYSTEM_CFG_ALLOW_HOST_SLAVE_WITHOUT_IBUS` | 无遥控器主机接管行为 |
| 改 `SYSTEM_CFG_HOST_SLAVE_KEEP_DRIVE_POWER` | session 中断后的电源保持行为 |
| 改 `SYSTEM_CFG_JOINT_*` | 回零流程、行程上限、关节位置换算 |
| 改轮参数 | 手动模式与主机模式下速度响应 |
| 改灯带映射 | 四角颜色和转向灯方向 |

### 4.2 协议改动后验证

- 新字段能被 `uart_task_apply_command()` 正确解析
- 无旧字段回归问题
- telemetry 新字段只反映真实状态
- 主机端和设备端字段编号一致

## 5. 推荐的代码观察点

| 目标 | 观察点 |
| --- | --- |
| 命令是否进系统 | `host_control_cmd_t` |
| 控制层是否生成意图 | `robot_motion_cmd_t` |
| 模式是否正确 | `ROBOT_MODE_T` |
| 执行层是否被拦截 | `input_status_t`、回零状态、force disable |
| 电机反馈是否更新 | `motor_info_t` |
| 遥测是否真实 | `telemetry_service_snapshot_t` |

## 7. 后续建议

如果后续要补测试，建议优先级如下：

1. host 协议解析和打包单元测试
2. 模式机切换与 freshness 逻辑测试
3. 关节回零状态机测试
4. telemetry 聚合逻辑测试
5. CAN drop / recover 行为测试
