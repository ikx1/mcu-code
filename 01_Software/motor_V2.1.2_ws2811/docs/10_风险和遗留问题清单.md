# 10 风险和遗留问题清单

> 文档状态：当前权威文档
> 适用基线：STM32F429ZET6 + HAL/LL + FreeRTOS(CMSIS-RTOS v2)
> 对应工程：motor_V2.1.1_ws2811
> 说明：本文档汇总当前工程已知风险、历史包袱和建议后续处理项

## 1. 当前最高风险项

### 1.1 关节回零状态机复杂且集中

风险说明：

- 回零流程涉及驱动状态、限位输入、超时、故障和位置复位
- 一旦修改不当，可能导致关节不动作、误归零或故障锁死

建议：

- 修改前先完整跑通当前流程
- 优先通过配置和限位映射调整解决问题
- 如需改状态机，必须同步回归回零成功、回零失败、急停打断三类路径

### 1.2 新旧串口链路并存

风险说明：

- UART1 走新协议栈
- `USART2/USART3/UART4` 当前仍走旧串口桥接，`UART8` 作为超声波预留链路保留在 legacy 体系
- 接手人容易误以为所有串口都已统一到同一套框架

建议：

- 修改串口逻辑前，先确认自己改的是新栈还是旧桥接
- 不要把 UART1 的协议假设套到其他串口上

### 1.3 文档历史包袱仍然存在

风险说明：

- 仓库中仍保留多份历史背景文档
- 其中部分内容来自旧平台和旧架构阶段

建议：

- 以当前权威文档和源码为准
- 历史文档只做背景参考

### 1.4 关节状态兼容码仍有硬编码

风险说明：

- 业务层当前仍把 `0x0433u` 当作关节使能兼容态使用
- 该状态值没有在驱动层以命名常量统一定义

建议：

- 后续应把兼容状态码收敛到驱动层定义
- 不要在控制、执行、遥测多处重复写裸值

## 2. 当前行为容易被误判的点

### 2.1 READY 模式允许保持驱动上电

风险说明：

- 当前默认 `SYSTEM_CFG_READY_KEEP_DRIVE_POWER = 1`
- 现场观察到 READY 下驱动仍上电，不代表异常

### 2.2 无遥控器时允许上位机接管

风险说明：

- 当前默认 `SYSTEM_CFG_ALLOW_HOST_SLAVE_WITHOUT_IBUS = 1`
- 无遥控器并不一定回到 READY，只要主机 session 与命令 freshness 满足，就可能进入 `SUB_SLAVE`

### 2.3 主机命令收到不等于动作执行

风险说明：

- 通信层只写 mailbox
- 控制层只生成意图
- 执行层仍可能因急停、disable、未回零、未使能而拦截

### 2.4 telemetry 不是命令回显

风险说明：

- 上位机看到的 `status_word`、轮速和关节状态是结果态，不是意图态
- 如果执行层拦截了动作，遥测不会“假装成功”

### 2.5 关闭自动回零不等于硬件一定安全

风险说明：

- 当前 `SYSTEM_CFG_JOINT_AUTO_HOME_ON_BOOT = 0` 会把关节直接视为已回零
- 如果现场不是绝对编码器或没有可靠零位保持，上层会误以为关节可直接动作

## 3. 历史命名与实现不一致项

### 3.1 `ws2811/ws2812` 命名沿用历史

实际情况：

- 业务层仍叫 `ws2811/ws2812`
- 但当前硬件和适配已经是现板级灯带实现

### 3.2 `ContronlTask` 拼写历史遗留

实际情况：

- 拼写错误来自历史代码延续
- 当前不要因为名字不标准就随意大改，避免连锁影响

### 3.3 某些注释仍保留旧平台背景

实际情况：

- 代码和旧文档中仍有历史阶段的描述痕迹
- 阅读时应以当前行为为准，不以命名或旧注释为准

## 4. 当前测试与验证风险

### 4.1 自动化测试不足

风险说明：

- 当前缺少协议、模式机、回零状态机的自动化回归测试
- 大部分验证仍依赖现场联调和断点观察

建议：

- 后续优先补协议层和回零状态机测试

### 4.2 多构建目录并存

风险说明：

- `MDK-ARM` 下存在多个历史构建目录
- 接手时容易误判哪个版本是当前有效输出

建议：

- 以当前使用的工程配置为准，不参考旧 `Build_*` 目录内容判断行为

## 5. 当前技术债

### 5.1 协议层缺少独立单元测试

影响：

- 改 TLV 字段、字节序或 CRC 逻辑时，回归成本高

### 5.2 模式机与执行策略高度依赖人工理解

影响：

- 新同事接手成本高
- 小改动容易引入行为性回归

### 5.3 关节回零故障恢复路径较重

影响：

- 现场排障需要较多状态判断
- 自动恢复能力有限

## 6. 后续建议优先级

1. 为 UART1 协议补单元测试
2. 为模式机和 freshness 逻辑补回归测试
3. 为关节回零状态机补场景验证脚本
4. 清理旧构建目录和历史无效口径
5. 视需要统一更多旧串口链路行为
